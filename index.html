How the verification works

  1. Hash. SHA-256 turns the PDF into a 256-bit fingerprint. Finding a second file with the same digest is computationally infeasible, so the digest stands in for the file.
  2. Sign a statement, not just bytes. manifest.json says who signs, what (file name, size, digest) and when. I sign that statement with an Ed25519 private key that never leaves my computer.
  3. Verify. Anyone with the public key can check the signature and recompute the digest. A change to either the statement or the PDF makes verification fail.
What this does not prove. A valid signature shows the file was approved by whoever holds this key. It does not by itself show that the key is mine: someone who controlled this website could replace the PDF, the manifest and the key together. That is the key-distribution problem, so I also publish the key fingerprint through separate channels (my GitHub profile and on request by email) for you to compare. It also says nothing about confidentiality; the CV is public on purpose.

The same three questions (who signed, what exactly was signed, and why trust that key) are the ones an AI agent faces before acting on another agent’s message or on a user’s delegated authority. That is the problem I want to work on.
